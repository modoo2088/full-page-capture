# Full Page Capture (풀 페이지 캡처)

> **v1.0.1** — Chrome 캡처 속도 제한(초당 2회) 대응: 자동 스로틀 + 재시도, 오류 메시지 중복 표시 수정.

웹페이지가 아무리 길어도 **버튼 한 번**으로 맨 위부터 맨 아래까지 전체 캡처하고,
PNG / PDF / 클립보드로 바로 사용할 수 있는 Chrome 확장프로그램입니다.

- 개발자도구나 복잡한 조작 없이 확장 프로그램 버튼만 누르면 됩니다.
- **모든 처리는 브라우저 안에서만** 이루어집니다. (No Upload / No External Server / Local Processing Only)
- Manifest V3 기준, Chrome 최신 버전에 대응합니다.

---

## 1. 주요 기능

| 기능 | 설명 |
|---|---|
| 전체 페이지 캡처 | 세로로 아무리 긴 페이지(3,000px / 8,000px / 20,000px 이상)도 자동 스크롤하며 한 장의 이미지로 합성 |
| 현재 화면 캡처 | 지금 보이는 화면(viewport)만 캡처 |
| PNG 저장 | 원본 해상도 유지(Retina/고해상도 devicePixelRatio 반영) |
| PDF 저장 | A4 세로형 여러 페이지 자동 분할(기본값), 비율 왜곡 없음 |
| 클립보드 복사 | 카카오톡/Slack/Notion/ChatGPT/문서편집기에 바로 붙여넣기 |
| 미리보기 | 썸네일 클릭 시 큰 이미지로 확인(확대/축소 지원) |
| 파일명 자동 생성 | `사이트명_페이지제목_YYYY-MM-DD_HHmm` 형식 |
| 진행률 표시 | `3 / 12 영역 캡처 중 · 25%` 형태로 진행 상황 표시 |
| 스크롤 위치 복원 | 캡처가 끝나면 원래 보고 있던 위치로 자동 복귀 |
| sticky/fixed 중복 방지 | 상단 고정 메뉴·플로팅 버튼 등이 반복 합성되지 않도록 처리(정상 header는 첫 화면에 1회 포함) |
| 설정 기억 | 마지막으로 사용한 캡처 종류/저장 형식만 `storage.local`에 저장 |

## 2. 설치 방법 (개발자가 아니어도 5분이면 됩니다)

> 준비: `full-page-capture_v1.0.0.zip` 파일의 압축을 풀어 폴더를 적당한 곳에 둡니다.
> (예: 바탕화면의 `full-page-screenshot` 폴더. **이 폴더를 옮기거나 삭제하면 확장이 작동을 멈추므로** 잘 보관할 위치에 두세요.)

1. Chrome 주소창에 `chrome://extensions` 입력 후 Enter
2. 화면 **우측 상단**의 **개발자 모드** 토글을 **ON**
3. 좌측 상단 **압축해제된 확장 프로그램을 로드합니다** 클릭
4. 압축 해제한 **`full-page-screenshot` 폴더 자체**를 선택 (폴더 안의 파일이 아니라 폴더 선택)
5. 목록에 **Full Page Capture** 가 나타나면 성공
6. Chrome 상단 **퍼즐 모양 아이콘(확장 프로그램)** → Full Page Capture 옆 **핀 아이콘** 클릭해서 고정

확인: Chrome 우측 상단에 파란 카메라 아이콘이 고정되면 설치 완료입니다.

### 업데이트 / 제거
- 업데이트: 폴더 내 파일을 교체한 뒤 `chrome://extensions` 목록에서 해당 카드의 **새로고침(↻)** 버튼 클릭
- 제거: `chrome://extensions` 목록에서 **삭제** 클릭

## 3. 사용 방법

### 전체 페이지 캡처 (기본 흐름)
1. 캡처할 웹페이지 열기
2. Chrome 우측 상단 확장 프로그램 아이콘 클릭
3. **[ 전체 페이지 캡처 ]** 클릭
4. 진행률 확인 (`n / N 영역 캡처 중 · %` → `이미지 합성 중...`)
5. **캡처 결과 준비 완료** 가 나오면 선택:
   - **[ PNG 저장 ]** → 다운로드 폴더에 PNG 저장
   - **[ PDF 저장 ]** → A4 여러 페이지 PDF 저장
   - **[ 클립보드에 복사 ]** → "클립보드에 복사되었습니다." 안내 후 어디든 붙여넣기(Ctrl/Cmd+V)
6. 썸네일을 클릭하면 큰 이미지로 미리 확인 가능
7. 결과 아래 **파일명** 칸은 직접 수정할 수도 있습니다

끝. 캡처가 끝나면 원래 보고 있던 스크롤 위치로 자동 복귀합니다.

### 현재 화면 캡처
같은 팝업에서 **[ 현재 화면 캡처 ]** 클릭. 보이는 영역만 캡처됩니다.

### 팁
- 전체 캡처 중에는 페이지가 자동으로 스크롤됩니다. 팝업 창을 닫아도 백그라운드에서 계속 진행되며, 다시 열면 진행 상황이 이어서 표시됩니다.
- 매우 긴 페이지는 캡처에 수 초~수십 초 걸릴 수 있습니다(진행률로 확인 가능).

## 4. 파일명 규칙

기본 형식: `사이트명_페이지제목_YYYY-MM-DD_HHmm.png` (PDF는 `.pdf`)

예시: `moduos_선거예산관리_2026-09-25_0915.png`

- 사이트명: 도메인에서 `www.`와 TLD(.com/.kr 등)를 제외한 부분
- 파일명에 사용할 수 없는 특수문자(`/ : * ? " < > |` 등)는 자동 제거
- 지나치게 긴 이름은 자동 축소(전체 90자 이내)
- 같은 이름의 파일이 있으면 Chrome이 자동으로 `(1)`, `(2)` 붙임

## 5. 권한 안내 (최소 권한 원칙)

| 권한 | 사용 목적 |
|---|---|
| `activeTab` | **버튼을 누른 순간의 현재 탭만** 대상. 페이지 제목/URL 읽기와 화면 캡처에 사용 |
| `scripting` | 캡처 시에만 현재 탭에 스크롤 제어 스크립트 주입(자동 스크롤/복원용) |
| `downloads` | PNG/PDF 파일 저장 |
| `storage` | 마지막 사용 설정(캡처 종류/저장 형식)과 직전 캡처 결과 저장 |
| `unlimitedStorage` | 매우 긴 페이지의 캡처 이미지(수십 MB)도 저장 결과가 사라지지 않도록 |
| `clipboardWrite` | 클립보드 복사 |

**불필요한 권한은 넣지 않았습니다.**
- `tabs`(모든 탭 정보) 권한 없음 → `activeTab`으로 충분
- `host_permissions`(모든 사이트 데이터 읽기) 없음 → 콘텐츠 스크립트를 상시 설치하지 않고, 버튼을 누른 순간에만 현재 탭에 임시 주입

## 6. 캡처할 수 없는 페이지

다음 페이지는 Chrome 자체 보안 정책으로 캡처가 불가능하며,
안내 문구 **"Chrome 보안 정책으로 인해 이 페이지는 캡처할 수 없습니다."** 가 표시됩니다.

- `chrome://` , `about:` , `devtools://` 등 Chrome 내부 페이지
- Chrome 웹 스토어
- 보안 정책으로 스크립트 주입이 차단된 페이지

### file:// 로컬 파일 페이지
기본적으로 차단됩니다. 필요하면:
`chrome://extensions` → Full Page Capture → **세부정보** → **파일 URL에 대한 액세스 허용** ON

## 7. 긴 페이지 / 성능 안내

- 캡처는 Chrome 정책상 영역당 최소 0.6초 간격으로 진행됩니다(초당 2회 제한 준수). 예: 15영역 페이지는 약 10~15초 소요.

- 매우 긴 페이지(약 25,000px 이상, 고해상도 모니터 기준)는 브라우저의 이미지 크기 한도(약 1.6억 픽셀)에 따라 자동 축소 저장될 수 있습니다. 이 경우 결과 화면에 "브라우저 이미지 크기 한도로 축소 저장되었습니다" 안내가 표시됩니다.
- 무한 스크롤 페이지는 시작 시점 높이 기준으로 캡처하며, 그보다 더 늘어나는 부분은 잘립니다("일부만 캡처" 안내 표시).
- lazy 로딩 이미지는 캡처 전 빠른 예비 스크롤로 미리 불러옵니다.
- 페이지 중간의 스크롤 영역(관리자 대시보드 등)도 자동 감지하여 캡처합니다.
- DRM 보호 영상이 있는 페이지는 해당 영역이 검게 나올 수 있습니다(Chrome 정책).

## 8. 문제 해결 (FAQ)

**\"Chrome의 캡처 속도 제한(초당 2회)에 걸렸습니다\" 라고 나와요**
- Chrome이 화면 캡처 API를 초당 2회로 제한하기 때문입니다. v1.0.1부터는 캡처 호출을 자동으로 조절하고, 제한에 걸리면 자동으로 기다렸다 재시도합니다. 오류가 반복되면 몇 초 뒤 다시 시도해 주세요.

**클립보드 복사가 실패해요**
- 팝업을 다시 열고 버튼을 다시 눌러보세요. 이미지가 매우 큰 경우(수십 MB)는 시스템 제한일 수 있습니다. PNG 저장을 이용해 주세요.

**전체 캡처가 중간에 멈춘 것 같아요**
- 진행률 표시가 계속 움직이는지 확인하세요. 합성 단계는 시간이 더 걸릴 수 있습니다. 팝업을 닫아도 백그라운드에서 계속됩니다.

**sticky 메뉴가 두 번 나와요**
- 드물게 CSS가 특수하게 구성된 페이지에서 발생할 수 있습니다. 이슈로 알려주시면 개선에 반영합니다.

**캡처 이미지가 흐릿해요**
- 브라우저 줌(확대/축소) 상태에서 캡처하면 픽셀 밀도가 달라질 수 있습니다. 100% 줌에서 캡처해 보세요.

**특정 사이트에서 아예 안 돼요**
- 사이트의 보안 정책(CSP)으로 스크립트 주입이 막혔을 수 있습니다. 6번 항목을 참고하세요.

## 9. 개인정보 / 보안

- 캡처 이미지, 페이지 URL, 파일명 등 **그 어떤 데이터도 외부로 전송하지 않습니다.**
- 네트워크 요청 없음, 분석(analytics) 없음, 서버 없음.
- PDF 생성 라이브러리(jsPDF, MIT 라이선스)도 확장 프로그램 폴더 안에 포함되어 있어 CDN 로딩이 없습니다. (Manifest V3 CSP 준수)
- 저장되는 정보는 `storage.local` 안의 두 가지뿐입니다:
  1. 마지막 사용 설정(캡처 종류, 저장 형식)
  2. 가장 최근 캡처 결과(다음에 팝업을 열었을 때 결과를 이어서 쓰기 위함)

## 10. 폴더 구조

```
full-page-screenshot/
├── manifest.json        # 확장 프로그램 설정 (Manifest V3)
├── popup.html           # 팝업 UI
├── popup.css            # 팝업 스타일
├── popup.js             # 팝업 동작(캡처 요청/진행률/저장/복사)
├── background.js        # 백그라운드 서비스 워커(캡처 오케스트레이션/합성)
├── content.js           # 페이지 쪽 스크립트(스크롤 제어, sticky/fixed 처리)
├── capture.js           # 캡처 실행 모듈(주입 → 세그먼트 캡처 → 합성 → 저장)
├── pdf.js               # PDF 생성(A4 자동 분할)
├── utils.js             # 공용 유틸리티(세그먼트 계산, 파일명, 합성)
├── preview.html / preview.js  # 큰 이미지 미리보기 페이지
├── vendor/
│   └── jspdf.umd.min.js # jsPDF 2.5.2 (MIT, 로컬 번들)
└── icons/               # 아이콘 16/32/48/128
```
